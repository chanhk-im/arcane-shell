# Arcane Shell — UI 명세서 v1.0

> 컨셉: "마법 = 코드/인프라". UI는 실제 개발자 터미널/IDE를 흉내낸 미학을 유지합니다. 화려한 판타지 UI가 아니라 **모노스페이스 폰트, 다크 테마, 텍스트 로그 중심**의 CLI 감성이 핵심입니다.

---

## 0. 디자인 원칙

1. **터미널이 주인공, 패널은 보조**. 메인 화면의 60% 이상은 항상 터미널(명령어 입출력)이 차지합니다.
2. **색상은 의미를 가질 때만 사용** (상태 표시, 속성, 희귀도). 장식 목적의 색상 남용 금지.
3. **모든 수치 변화는 터미널 로그에도 텍스트로 남습니다** — 패널 UI만 보고는 알 수 없는 정보가 없어야 함(스크린리더/로그 재생 관점에서도 유리).
4. **폰트는 모노스페이스 고정** (예: JetBrains Mono, D2Coding). 숫자 정렬이 자주 필요하므로 가변폭 폰트 사용 금지.
5. 다크 테마 기본, 라이트 테마는 범위 밖(필요 시 후속).

## 1. 전체 레이아웃

```
┌─────────────────────────────────────────────────────────┐
│  상단바: 마나/HP게이지 · 마석 5등급 잔량 · 골드 · 명성      │
├───────────────────────────────┬───────────────────────────┤
│                                │  사이드 패널 (탭 전환)      │
│      메인 터미널 영역           │  [트리|부품|룬|유물|도감|   │
│   (명령어 출력 로그, 스크롤)    │   스크립트|길드|경매장|균열| │
│                                │   문서|도움말]               │
│                                │                             │
├───────────────────────────────┴───────────────────────────┤
│  명령어 입력줄 (>_)                                          │
└─────────────────────────────────────────────────────────┘
```

- **상단바**: 항상 고정, 실시간 갱신 (틱마다). 마나 게이지는 가동률 하락 시 색상 경고(아래 5-2)
- **메인 터미널**: 명령어 입출력, 전투 로그, 스크립트 실행 로그가 여기 누적. 최근 200줄만 유지(무한 누적 금지, CLAUDE.md 원칙과 동일)
- **사이드 패널**: 탭으로 전환되는 서브 화면들. 랭크 진행에 따라 탭이 순차적으로 해금(회색 비활성 탭으로 미리 보여주되 잠금 아이콘 표시)
- **입력줄**: 명령어 직접 입력 + 자동완성(Tab 키)

### 1-1. 반응형
- 데스크톱 우선 설계(최소 1024px). 모바일은 사이드 패널이 터미널 아래로 쌓이는 세로 배치로 전환(범위 밖, 후속 설계 필요 — 여기선 데스크톱만 명세)

## 2. 상단바 상세

| 요소 | 표시 방식 |
|---|---|
| 마나 게이지 | `[████████░░] 82/100` 형태, 텍스트+바 병기 |
| 마나 가동률 경고 | 가동률 < 80%일 때 게이지 테두리 주황, < 60%일 때 빨강 (5절 색상 규칙 참조) |
| 마석 5등급 | 아이콘+숫자 5개 나열, 등급색(6절) 적용. 현재 획득 불가능한 등급(미해금)은 표시 안 함 |
| 골드/명성 | 텍스트만, 아이콘 최소화 |

## 3. 사이드 패널 — 화면별 명세

### 3-1. 아르카나 트리
- 55깊이 그래프를 **줌 가능한 노드맵**으로 표시 (랭크10개 구간을 세로 밴드로 구분, 랭크 경계에 구분선)
- 노드 색상: 해금 전(회색) / 해금 가능(흰 테두리 깜빡임) / 강화 중(스탯색) / 만강(금테두리)
- 노드 하나 클릭 시 사이드에 상세 카드: 담당 스탯, 현재 강화수치, 다음 강화 비용, 다음 강화 시 증가량
- 해금 노드(스크립트/길드 등 12종)는 일반 노드와 **모양 자체를 다르게**(원이 아니라 사각형) 구분

### 3-2. 부품 정비소
- CPU/GPU/HDD/RAM/메인보드 5슬롯을 가로로 배치
- 슬롯 카드: 등급(색상), 강화 레벨(`Lv.17/25` 표기), 주스탯 수치, 보조옵션 수치
- 하단에 "제작" / "강화" / "계승" 3개 탭 버튼 — 각각 별도 서브뷰로 전환
- 제작 탭: 필요 보스재화 종류/수량과 보유량 비교 표시(부족하면 빨간 텍스트)

### 3-3. 룬 각인
- 부품 5슬롯 각각에 룬 소켓 1개 — 부품 정비소 화면과 시각적으로 연동(같은 슬롯 배치 재사용)
- 룬 카드: 희귀도(색상, 6절) + 옵션 3~5줄 리스트, 옵션마다 옵션등급 표시(별 아이콘 개수 등)
- 리롤 버튼(잔여 횟수 표시, 예: `리롤 (2/3)`), 합성 버튼(동일 룬 3개 선택 시 활성화)

### 3-4. 유물
- 5종 카드 그리드, 보유/미보유 구분(미보유는 실루엣 처리)
- 카드 클릭 시 장착/해제 토글 (동시 장착 1개 제한 — 다른 유물 선택 시 자동 교체, 확인 모달 없이 즉시 반영하되 터미널 로그에 "유물 교체: A → B" 기록)

### 3-5. 몬스터 도감
- 6속성 × 진행바 형태 (`화속성 [███████░░░] 350/500`)
- 티어별 상세는 아코디언으로 펼쳐서 개별 몬스터 HP/방어/드랍 정보 열람 가능(읽기 전용, 위키형)

### 3-6. 스크립트 에디터
- 좌: 코드 에디터(문법 하이라이팅, 최소 기능). 우: 실행 로그 + 현재 메모리 사용량(`3.2/10 MB` 형태 게이지)
- 상단에 [실행] [정지] [저장] [문서] 버튼, 저장된 스크립트 목록을 드롭다운으로 전환
- **[문서] 버튼**: 우측 패널을 실행 로그 대신 3-12의 API 문서 패널로 전환(토글). 코드 작성 중 바로 참조하는 게 핵심이라 별도 화면 이동 없이 같은 화면 안에서 전환
- 랭크7 이후: 매크로 탭 추가 — 여러 스크립트를 슬롯에 드래그해서 묶는 UI(슬롯 2~4개, 부품 정비소처럼 슬롯 카드 형태 재사용)
- 에러 발생 시(캐치 안 된 예외) 에디터 좌측 라인 넘버에 빨간 마커 + 터미널에 에러 로그 출력. 이때 문서 패널이 자동으로 해당 에러 타입(`InsufficientManaError` 등) 설명 항목으로 스크롤

### 3-7. 마법 길드
- 3개 서브탭: 환전 / 의뢰 / 마법사 등급
- 환전: 마석 등급별 슬라이더 또는 수량 입력 → 예상 골드 실시간 계산 표시
- 의뢰: 카드 리스트(퀘스트 목표 + 보상), 완료 가능한 것은 강조 테두리
- 마법사 등급: 현재 명성 게이지 + 다음 등급까지 필요량, 등급업 시 해금되는 트리 노드 미리보기

### 3-8. 경매장
- 마석 등급별 보유량 + 환율 + "판매" 버튼 한 줄씩 나열(5줄 고정, 스크롤 없음)

### 3-9. 차원 균열
- 사냥터 카드 여러 개를 그리드로(기본1 + 균열 최대4 = 최대 5칸)
- 카드마다: 배정된 스크립트 이름, 현재 처치 상황(간단 통계), 활성/비활성 토글
- 미해금 슬롯은 잠금 아이콘 + 해금 조건 텍스트

### 3-10. 길드 레이드 / 리더보드
- 상단: 길드 주간 목표 진행바(협동), 하단: 개인 기여도 순위 테이블(경쟁)
- 리더보드 테이블은 가상화 적용(길드원 다수 시 성능 고려, CLAUDE.md 리스트 렌더링 원칙과 연결)

### 3-11. 차원 심층 (엔드 레이드)
- 별도 전용 화면(사이드 패널이 아니라 풀스크린 전환) — 엔드 콘텐츠로서 무게감을 주기 위한 유일한 예외
- 진행 중인 인스턴스 수(자동화 투자에 비례) + 전체 처치 속도 요약

### 3-12. API 문서 (`magic-hq.local`)
세계관상 "스크립트 공식 문서" 사이트라는 설정을 그대로 UI로 구현합니다 — 주소창처럼 상단에 `magic-hq.local/docs/...` 같은 가짜 경로를 표시해서 몰입감 유지.

- **전투 API / 자원 API** 두 섹션(`arcane_shell_script_api.md` 내용을 그대로 게임 내 문서로 이식)
- 함수 목록은 검색 가능한 리스트(좌측) + 선택 시 우측에 시그니처·설명·예시 코드
- 예시 코드 옆에 **"에디터에 삽입"** 버튼 — 클릭 시 3-6 스크립트 에디터의 현재 커서 위치에 그대로 붙여넣기 (실제 학습 곡선을 낮추는 핵심 장치)
- 새 콘텐츠 해금으로 API가 확장될 때마다(예: 차원균열-api) 문서에 **"NEW"** 배지가 붙은 새 섹션이 자동 추가되는 걸 원칙으로 (스크립트 API 명세서 4절 "향후 확장 시 규칙"과 연동)
- 랭크1(스크립트 해금) 시점부터 항상 접근 가능 — 잠금 없음

### 3-13. 도움말 (일반)
API 문서와 별개로, **게임 시스템 자체**에 대한 도움말입니다 (전투 공식, 마석 등급, 트리 구조 등 — 코드가 아니라 게임 개념 설명).

- 터미널에 `help` 또는 `help [키워드]` 입력 시 해당 항목 요약을 로그에 즉시 출력 (사이드 패널 이동 없이 빠르게 확인하는 용도)
- 사이드 패널 탭으로도 동일 내용 접근 가능(목차형 트리 구조 — 예: `전투 > 크리티컬 계산식`)
- **F1 키**로 현재 보고 있는 화면에 맞는 도움말 항목을 자동으로 열어줌(컨텍스트 인식) — 예: 룬 각인 화면에서 F1을 누르면 "룬 옵션 등급이란?" 항목이 바로 뜸
- 신규 콘텐츠 해금 시 관련 도움말 항목이 열리며 터미널에 `[NEW] 도움말에 '차원 균열' 항목이 추가되었습니다` 안내

## 4. 명령어 입력줄

- 기본 명령어(`spell`, `target`, `target set`, `help`)는 입력줄에서 직접 타이핑 가능
- `help`는 인자 없이 치면 전체 카테고리 목록을, `help [키워드]`는 해당 항목 요약을 즉시 로그 출력(3-13 참고)
- 사이드 패널 조작(강화, 장착 등)은 클릭 UI가 기본이지만, **모든 클릭 액션은 동일한 명령어로도 대체 가능**해야 함 (예: `rune reroll cpu` 같은 형태) — 스크립트 API 설계와 언어를 통일시키기 위한 원칙
- Tab 자동완성, 위/아래 화살표로 명령어 히스토리 탐색(터미널 표준 관례 유지)

## 5. 색상 규칙

### 5-1. 상태 색상 (전역 공통)
| 상태 | 색상 |
|---|---|
| 정상/성공 | 초록 |
| 경고 | 주황 |
| 위험/에러 | 빨강 |
| 비활성/잠금 | 회색 |
| 강조(해금 가능 등) | 흰색 깜빡임 |

### 5-2. 마나 가동률 경고 (2절 연동)
- 100~80%: 기본색(청록 계열)
- 79~60%: 주황
- 60% 미만: 빨강 (다만 설계상 하한이 67%이므로 실제로는 거의 발생하지 않음 — 발생 시 "룬/부품 재조정 필요" 신호로 기능)

### 5-3. 속성 색상 (6종, 고정 팔레트)
| 속성 | 색상(가안) |
|---|---|
| 화 | 빨강 계열 |
| 수 | 파랑 계열 |
| 뇌 | 노랑 계열 |
| 지 | 갈색/녹색 계열 |
| 성 | 흰색/금색 |
| 암 | 보라/검정 계열 |

### 5-4. 마석 등급 / 룬 희귀도 (5단계, 공통 팔레트 재사용)
| 등급 | 색상 |
|---|---|
| 1 | 흰색 |
| 2 | 초록 |
| 3 | 파랑 |
| 4 | 보라 |
| 5 | 주황/금색 |

이 5단계 팔레트는 **마석 등급, 룬 희귀도, 부품 등급, 옵션 등급에 전부 동일하게 재사용**합니다 — 등급이라는 개념을 시각적으로 통일시켜서, 유저가 색만 보고 "아 이게 높은 등급이구나"를 전 시스템에서 즉시 인지하게 하기 위함입니다.

## 6. 공통 컴포넌트 목록 (구현 우선순위용)

| 컴포넌트 | 용도 |
|---|---|
| `TerminalLog` | 메인 로그 출력, 200줄 상한 |

| `ProgressBar` | 마나/도감/균열 등 각종 진행률 (텍스트+바 병기 스타일 고정) |
| `GradeBadge` | 5단계 등급 팔레트 뱃지 (마석/룬/부품 공용) |
| `ElementIcon` | 6속성 아이콘+색상 |
| `SlotCard` | 부품/룬/매크로 슬롯 공용 카드 (재사용성 높음) |
| `NodeGraph` | 아르카나 트리 노드맵 시각화 |
| `ConfirmToast` | 클릭 액션 결과를 터미널 로그와 별개로 잠깐 보여주는 토스트(선택적, 즉시성 강화용) |
| `DocPanel` | API 문서(3-12) — 검색·목록·상세·"에디터에 삽입" 공용 |
| `HelpOverlay` | F1 컨텍스트 도움말(3-13), 현재 화면에 맞는 항목 자동 오픈 |

## 7. 남은 결정 필요 사항

1. 모바일/좁은 화면 레이아웃 — 이번 명세는 데스크톱 전용, 별도 설계 필요
2. `NodeGraph`(55노드 그래프)의 실제 좌표 배치 알고리즘 — 자동 레이아웃(force-directed 등) vs 수동 좌표 지정
3. 차원 심층만 풀스크린으로 예외 처리한 것이 UX상 일관성을 해치는지 — 플레이테스트 후 재검토 권장
4. 라이트 테마 지원 여부
5. 도움말이 "사이드 탭 + F1 오버레이 + `help` 명령어" 세 가지 진입점을 다 갖는 게 과한지 — 하나로 통합할지, 아니면 진입점이 여러 개인 게 오히려 접근성 면에서 좋은지 플레이테스트로 판단 필요
